# Antigravity Project Operating Rules

At the start of every session:
1. Read ~/.antigravity/projects.md if it exists.
2. Read .antigravity/brain_context.md.
3. Read .antigravity/todo.md.
4. Read .antigravity/tech_stack_guidelines.md.
5. Summarize current project state before changing files.

During work:
- Prefer small, tested changes.
- Before major edits, update todo.md with the active task.
- If a bug is fixed, log the cause and fix in tech_stack_guidelines.md.
- Never let memory files become junk drawers.

At the end of every meaningful task:
1. Update todo.md.
2. Condense brain_context.md if needed.
3. Add important architecture/bug/setup lessons to tech_stack_guidelines.md.
4. Update ~/.antigravity/projects.md if project scope, stack, or status changed.

Hard limits:
- brain_context.md max 150 lines.
- todo.md only active or next tasks; delete completed tasks.
- tech_stack_guidelines.md stores durable rules, not random notes.
